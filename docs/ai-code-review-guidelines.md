# AI コードレビューガイドライン

`/code-review`・`/security-review`、およびチャットでの単発のレビュー依頼で使う観点。
指摘には、問題の内容、具体的な発生シナリオ、修正案の3点を含める。

## 1. 3省2ガイドライン整合性チェック

| 観点 | 確認内容 |
|---|---|
| リージョン | 医療情報を扱うリソースが国内リージョン（ap-northeast-1 / ap-northeast-3）に限定されているか。レプリケーション先・バックアップコピー先も含めて確認する |
| 保存データの暗号化 | S3 / EBS / RDS / CloudWatch Logs / Secrets Manager 等で KMS CMK による暗号化が有効か。キーローテーションが有効か |
| 通信の暗号化 | ALB / CloudFront が TLS 1.2 以上か。HTTP はリダイレクトのみか。S3 バケットポリシーで `aws:SecureTransport=false` を拒否しているか |
| 最小権限 | IAM ポリシーに不要な `*`（Action / Resource）がないか。サービスプリンシパルに `aws:SourceArn` / `aws:SourceAccount` 条件があるか |
| MFA・パスワード | 管理アクセスは IAM Identity Center + MFA か。パスワードポリシーで定期変更を強制していないか、ロックアウトを優先しているか（厚労省GL第7.0版 システム運用編14章） |
| ネットワーク分離 | 医療情報を扱うリソースがプライベートサブネットにあるか。SG に `0.0.0.0/0` からの受信がないか（公開 ALB の 443 を除く）。DB サブネットにインターネットへの経路がないか |
| 監査ログ | CloudTrail・VPC Flow Logs・アクセスログが有効か。ログバケットに Object Lock とパブリックアクセスブロックが設定されているか |
| バックアップ・BCP | マルチ AZ 構成か。バックアップと DR（大阪リージョン）を考慮しているか。削除保護（`deletion_protection` / `prevent_destroy`）があるか |
| テナント分離 | テナント間でデータを参照できる経路がないか（IAM・KMS キーポリシー・S3 プレフィックス・DB の RLS） |
| 責任分界 | AWS 責任共有モデル上、事業者の責任となる設定が漏れていないか |

## 2. セキュリティ（OWASP Top 10 ほか）

- A01 アクセス制御の不備：テナント分離、IAM の過剰権限、パブリックな S3／スナップショット
- A02 暗号化の失敗：平文での保存・通信、AWS 管理キーへの意図しないフォールバック
- A05 セキュリティ設定ミス：デフォルト SG の許可ルール、IMDSv1、公開エンドポイント
- A09 ログとモニタリングの不備：ログの無効化、保持期間不足、改ざん可能なログ保管
- 機密情報：`terraform.tfvars`・コード・出力値にパスワードやキーが含まれていないか（`sensitive = true` の付与を含む）

## 3. Terraform の品質

- CLAUDE.md のディレクトリ規約（カテゴリ別モジュール、`environments/_shared` のシンボリックリンク運用）に従っているか
- 環境ごとの差分が `terraform.tfvars` だけで吸収されているか
- `variable` に `description`・型・必要に応じて `validation` があるか
- 破壊的変更（リソースの置き換え、Object Lock の COMPLIANCE モード化等）を含む場合、その影響を明記しているか
- README.md のディレクトリ構成が実装と一致しているか
